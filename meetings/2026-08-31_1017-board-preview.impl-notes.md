## 設計決定 (Design decisions)

- **Module placement** — Issue #1017 / design.md §3.6 ⚠️ 型別約束: `BoardPreview` lives in
  `GameShellKit` (zero deps), `ResumeCandidate<Route>` in `GameAppKit` references it. Confirmed
  by reading `GameShellKit/Package.swift` has no dependencies before adding the type.
- **`BoardPreview` init is failable, not throwing** — `init?(columns:rows:cells:)` returns `nil`
  when `cells.count != columns * rows` or a dimension is non-positive, rather than a
  precondition/trap. Matches the issue's explicit preference and the overall degrade contract
  (malformed data → no preview, never a crash).
- **CellMark semantics per app**:
  - Sudoku: `.` → `.empty`; a digit at a `givenMask`-true index → `.given`; a digit at a
    `givenMask`-false index → `.filled`.
  - Minesweeper: `Cell.state` `.hidden` → `.empty`, `.revealed` → `.filled`, `.flagged` → `.marked`
    (a direct 1:1 mapping — no ambiguity here, unlike Sudoku's given/filled split).
- **Sudoku mapper needs `givenMask`, not just `boardState`** — the encoded board string alone
  (`SavedGameSummary.boardState`, an 81-char '.'/digit string) cannot distinguish a clue from a
  player-entered digit; that information only exists on `Puzzle.clues.givenMask`. Rather than
  widen `SavedGameSummary` to carry the whole `Puzzle`, `Live.swift`'s `fetchResume` closure
  additionally calls `puzzleProvider.puzzle(for: summary.puzzleId)` (captured from the outer
  `live()` scope) and passes `puzzle?.clues.givenMask ?? []` into the pure
  `SudokuBoardPreviewMapper.make(boardState:givenMask:)`. Verified `puzzleProvider.puzzle(for:)`
  (`SudokuKit/Sources/SudokuPersistence/PuzzleStore.swift:86`) is a **deterministic local
  regeneration** from the puzzleId's encoded seed — no CloudKit/network call — so this does not
  violate the issue's "no new CloudKit fetch" constraint (it's the same kind of lookup
  `Persistence.loadOrCreate` already performs to restore a board). A `puzzleProvider` failure is
  caught with `try?` and degrades to an empty givenMask, which the mapper's length-mismatch guard
  turns into a `nil` preview — resume itself is unaffected.
- **Minesweeper mapper decodes the raw blob itself** — `MinesweeperSavedGameSummary` gained a raw
  `stateBlob: Data?` (the untouched CK bytes) rather than a pre-decoded snapshot/cell array, so
  `MinesweeperPersistence` doesn't need to know about `BoardPreview`/`GameShellUI` at all. The
  JSON decode (`MinesweeperSessionSnapshot.self`) happens inside the pure
  `MinesweeperBoardPreviewMapper.make(stateBlob:)` in the composition-root target, wrapped in
  `try?` → `nil` on any decode failure.
- **Both `SavedGameSummary.boardState` and `MinesweeperSavedGameSummary.stateBlob` are new
  optional fields with `nil` defaults** — added to the memberwise inits with default values so
  every existing call site (tests included) keeps compiling unmodified.

## 折衷 (Tradeoffs)

- **Where to test the two mappers** — Sudoku already has a dedicated `SudokuAppCompositionTests`
  target, so `SudokuBoardPreviewMapperTests.swift` landed there directly. MinesweeperKit has NO
  dedicated `MinesweeperAppCompositionTests` target (only `MinesweeperPersistenceTests` +
  `MinesweeperUITests`, and `MinesweeperUITests` already depends on `MinesweeperAppComposition`
  + `GameShellUI` + `MinesweeperGameState` for `LiveRouteFactoryTests.swift`). Rather than stand
  up a new test target just for one mapper file, `MinesweeperBoardPreviewMapperTests.swift` was
  added to the existing `MinesweeperUITests` target, following the precedent
  `LiveRouteFactoryTests.swift` already set for testing `MinesweeperAppComposition` internals
  from that target.
