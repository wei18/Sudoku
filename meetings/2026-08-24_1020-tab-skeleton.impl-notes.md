## 設計決定 (Design decisions)

- **`AppTab` SF Symbols = `calendar` / `dice` / `chart.bar`** — dispatch says
  "reuse the repo's existing daily/practice/stats sidebar icons". `HomeMode`
  (`GameShellUI/Home/HomeScreen.swift`, being deleted) used `calendar` for
  `.daily` and `dice` for `.practice`; the `#773`/`#844` Statistics entry used
  `chart.bar` (`GameAppKit/GameHomeView.statsLink`). `docs/designs/v3/prototype.html`
  draws Today as a calendar, Progress as a bar chart, and Practice as a 9-cell
  grid — the first two agree with the repo symbols; for Practice the repo's
  `dice` is kept per the dispatch's "reuse" instruction rather than switching to
  `square.grid.3x3`. Flagging for Leader: prototype vs repo disagree on Practice
  only.

- **Tab-title / "Achievements" strings live in the two APP catalogs, not a
  GameShellUI catalog** — GameShellUI ships **no** string catalog at all (see the
  `HomeMode.titleKey` doc: "GameShellUI ships no string catalog of its own";
  `Text(LocalizedStringKey)` resolves against `Bundle.main`). So the only place
  these keys can live is `App/Sudoku/Resources/Localizable.xcstrings` and
  `App/Minesweeper/Resources/Localizable.xcstrings`. See §偏離 for the fixture
  consequence.

- **`HomeModeCard` / `HomeScreen` deleted wholesale** — verified by grep that the
  only *code* consumer of anything in `Home/HomeScreen.swift` outside the deleted
  `GameHomeView` is nothing; every other hit across SudokuKit / MinesweeperKit /
  `GameShellUI/DailyHubShellView.swift` is a **comment** referencing
  `HomeModeCard.cardPadding` / `HomeScreen.cardGridGap` as a spacing precedent.
  Those comments become stale references outside my scope (Stage B / a later
  doc pass); nothing stops compiling.

- **`LastSelectionStore` KEPT** — the dispatch said "delete if it only served
  home-mode memory". It does not: it backs Practice-difficulty persistence in
  `SudokuAppComposition/LiveRouteFactory.swift`,
  `MinesweeperAppComposition/LiveRouteFactory.swift`, and
  `MinesweeperUI/MinesweeperBoardView.swift` (tap-mode). Deleting it would break
  both apps for an unrelated reason. Verified by grep before deciding.

- **`GameConfig.title` removed** — after the rewrite nothing in
  GameShellKit/GameAppKit consumes it (`RootShellView` no longer takes a title;
  `GameHomeView.navigationTitle(title)` is deleted). Per the dispatch's "keep
  only if something still consumes it" and the repo's no-compatibility-shim
  principle, it is gone. Stage B sets per-tab titles with `.navigationTitle` in
  its own tab-root views.

- **Overlay hoisting registers only on the `false→true` edge** — so the hoisted
  view keeps a stable SwiftUI identity (its own `@State`, e.g. the completion
  surface's local animation flags) for as long as it is up. Consequence,
  documented in the API doc comment: values read *eagerly* while building
  `content()` are snapshotted at registration time. This is safe because
  `isActive` is by construction the disjunction of exactly the branches inside
  `content()`, so the branch taken at registration is the branch that made it
  active; `@Observable` reads inside the hoisted body stay live (observation
  registers on the hoisted view's own body evaluation) and `@Binding` / captured
  closures write through to live storage.

- **The iOS `fullScreenCover` board deliberately sees `coordinator == nil`** —
  `RootShellView` injects `\.boardModalOverlayCoordinator` *inside* its own body
  (onto the `TabView`), while `GameRoot` attaches `.fullScreenCover` to the
  **result** of `RootShellView`. Environment flows from the attachment point, so
  cover content inherits the default `nil` and the modifier renders in place —
  exactly the pre-#1020 behavior iOS already had, and the reason #1019's naive
  port only broke the pushed (macOS/iPad) case.

## 設計決定, 續 (Leader addenda, received mid-task)

- **`UITestLaunchTarget` replaces the `(String) -> Route?` resolve closure** —
  `-uitest-route daily|practice|settings|resumeFail` is how both E2E suites
  launch, and `daily` / `practice` named routes that are tab identities now, so
  a `Route?`-returning closure can no longer express them. The seam resolves
  into `enum UITestLaunchTarget { case tab(AppTab); case push(Route, tab: AppTab) }`
  with a `.push(route)` shorthand defaulting to `.today`. The launch-ARGUMENT key
  string is unchanged, so existing invocations keep working; only the per-app
  `resolve` closure's return type changes (Stage B).
  - Label is `tab:`, not the Leader's suggested `in:` — SwiftLint `identifier_name`
    hard-fails 1–2 character identifiers and rejected `in`.
  - Swift enum cases cannot carry default associated values, hence the static
    `push(_:)` factory rather than `case push(Route, tab: AppTab = .today)`.
  - The effect is factored into `UITestRouteModifier.apply(_:)` so it is testable
    without rendering, and the "replace, never append" property (a re-fired
    `onAppear` must not stack duplicates) is now pinned by a test rather than a
    comment.

- **`game.today.root` on `TodayTabHost`** — replaces the retired HOME scaffold's
  `game.home.root` (#935) as the locale-independent landing anchor for E2E
  "left the board, came back" assertions. `TodayTabHost` takes only plain
  injected inputs (root VM, adProvider, adGate, attPrimer, content), so it
  renders standalone in a snapshot host without the `makeGameApp` stack.

## 設計決定, 續 2 (Leader review fix — tab-root memoization)

- **`makeTabRoot` is now invoked exactly once per tab, at composition time.**
  Leader review caught a MAJOR defect in my first cut: `tabRoot` was a plain
  closure that re-ran `config.makeTabRoot(tab, deps, rootViewModel)` on every
  call, and `RootShellView.tabStack(for:)` calls it on every body evaluation.
  Stage B builds its hub view models (DailyHub / PracticeHub / Stats) inside
  that closure, so every render would have minted fresh models and wiped hub
  state — the #918 shape (`ReminderSettingsEntry` as a per-render factory,
  where an ancestor re-render replaced the model the user had just tapped and
  the primer sheet dismissed itself).
  - Fix: `memoizedTabRoots(_:)` in `MakeGameApp+Helpers.swift` builds all three
    roots into a `Dictionary` keyed by `AppTab` and returns a lookup closure.
    The Today wrapping happens inside the builder, so it is applied once too.
  - No force-unwrap: `AppTab.allCases` makes the dictionary total, and the
    `?? AnyView(EmptyView())` fallback exists so a future case added without
    rebuilding renders empty instead of trapping in a shipped app.
  - **Contract now documented on the helper**: `GameConfig.makeTabRoot` is
    invoked once per tab per launch and MUST be treated as a factory whose
    products have stable object identity. Stage B depends on this.
  - Accepted consequence: all three tab roots (and their view models) are
    constructed at launch, including tabs the player never opens. Lazy +
    memoized would only move the same allocation to first visit while adding a
    mutable cache, so eager is the simpler shape with identical steady state.
  - Test seam: `makeGameAppCore` cannot be called from a unit test — it wires
    the live CloudKit/GameKit/AdMob stack, and constructing that in an
    unentitled runner is the uncatchable-`CKException` trap CLAUDE.md warns
    about. `memoizedTabRoots` is the minimal seam the composition root routes
    through; `MemoizedTabRootsTests` asserts 3 builder calls total across 5
    further evaluations of every tab, plus per-tab instance stability.

## 折衷 (Tradeoffs)

- **`present(_:)` takes a `() -> AnyView` builder rather than storing the
  generic content** — considered making `BoardModalOverlayCoordinator` generic
  over the overlay content type; rejected because the coordinator lives in
  `EnvironmentValues` (which cannot carry a per-board generic parameter) and is
  shared by both games' differently-typed overlays. `AnyView` is already the
  established erasure in this shell (`RouteFactory.view(for:path:) -> AnyView`).

- **`BoardModalOverlayCoordinator.HoistedOverlay` is a top-level type** — nesting
  it would still satisfy SwiftLint's `nesting` rule (depth 1), but top-level
  keeps the `hoisted.view.id(hoisted.id)` call site in `RootShellView` readable
  and avoids a depth-2 typealias trap like the one `RootShellViewGenericityTests`
  documents.
